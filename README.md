# Tree-guided feature aggregation

Code and results for *A direct approach to tree-guided feature aggregation for high-dimensional regression* by Jinwen Fu, Aaron J. Molstad and Hui Zou.

The method aggregates features along a supplied tree for linear and logistic regression. This repository contains the simulations and microbiome analyses presented in the paper.

## 1. Contents

| Directory | Contents |
| --- | --- |
| `code/core_code/` | The `treeFA` R source package, shared R/C++ functions and MATLAB Relative Shift code. |
| `code/run code/simulations/` | R runners, Slurm submission scripts and plotting scripts for experiments 1–6. |
| `code/run code/real data study/` | Eleven real-data analyses and scripts for Table 1 and Figure 6. |
| `data/` | Real-data matrices, responses, feature trees, metadata and taxonomy. Scripts read directly from this directory. |
| `output/experiment1/` through `output/experiment6/` | Saved simulation results. |
| `output/real data study/` | Saved real-data results, grouped by analysis. |
| `manuscript/` | Figures, tables and ACC documents. |

Simulation data are generated by the runners. The real-data `.RData` files contain `data$X` (features), `data$y` (response) and `data$tree_df` (feature tree).

| Experiment | Setting | Figure |
| --- | --- | --- |
| 1 | Remove internal nodes from the feature tree. | 3 |
| 2 | Fix 20 groups and increase the number of features per group. | 4 |
| 3 | Linear regression: fix 100 features and increase the number of groups. | 5 |
| 4 | Linear regression: increase the number of features, with groups numbering approximately 25% of features. | 5 |
| 5 | Logistic regression: fix 20 groups and increase the number of features. | 5 |
| 6 | Increase the degree of tree misspecification. | 5 |

The real-data analyses cover Sinha (2016), Kim (2020), Jacobs (2016), Erawijantari (2020), Franzosa (2019), Wang (2020) and Yachida (2019). The `binary` and `continuous` folder suffixes identify the response type.

## 2. Platform and setup

Computations were performed on a Linux high-performance computing (HPC) cluster, with jobs submitted through Slurm. The saved analysis environment used R 4.2.3 on Ubuntu 22.04.5 LTS (x86_64) , with `treeFA` **0.0.2**, `rare` **0.1.1** and `glmnet` **4.1-8**. Figures 3–6 and Table 1 were reproduced on **macOS 26.6 (ARM64)** with R **4.6.1**. The plotting environment uses `ggplot2` **3.5.2**, `patchwork` **1.3.2** and `ggraph` **2.2.2**.

A C++ compiler is required to build `treeFA` and run Figure 6. Experiments 1–4 and 6 also use MATLAB for Relative Shift. Slurm runs use Bash and `sbatch`.

Run the following setup from the project root. Packages are installed in `code/core_code/rlib`, the library used by the R and Slurm scripts.

```bash
export TREEFA_R_LIB="$PWD/code/core_code/rlib"
mkdir -p "$TREEFA_R_LIB"
export R_LIBS="$TREEFA_R_LIB${R_LIBS:+:$R_LIBS}"

Rscript --vanilla - <<'RS'
lib <- Sys.getenv("TREEFA_R_LIB")
repos <- "https://cloud.r-project.org"
install.packages(c(
  "MASS", "Matrix", "Rcpp", "RcppEigen", "glmnet", "rare", "mclust", "pROC",
  "readr", "dplyr", "tidyr", "purrr", "tibble", "RColorBrewer", "colorspace",
  "igraph", "ggplotify", "patchwork", "car", "tidygraph", "ggraph", "remotes"
), lib = lib, repos = repos)
remotes::install_version(
  "ggplot2", version = "3.5.2", lib = lib, repos = repos, upgrade = "never"
)
RS

R CMD INSTALL --library="$TREEFA_R_LIB" "code/core_code/treeFA"
```

For MATLAB runs, put `matlab` on `PATH` or set `MATLAB_BIN` to its executable path. Table 1 uses standard R packages.

## 3. Reproduction

Run the commands below from the project root.

### Reproduce figures and Table 1

```bash
Rscript --vanilla "code/run code/simulations/experiment1/plot_figure3.R"
Rscript --vanilla "code/run code/simulations/experiment2/Figure 4.R"
Rscript --vanilla "code/run code/simulations/experiment3/Figure 5.R"
Rscript --vanilla "code/run code/real data study/Table 1.R"
Rscript --vanilla "code/run code/real data study/sinha_2016_binary/Figure 6.R"
```

| Result | Input | Output |
| --- | --- | --- |
| Figure 3 | `output/experiment1/` | `manuscript/figures/fig2joint.pdf` |
| Figure 4 | `output/experiment2/` | `manuscript/figures/Figure 4.pdf` |
| Figure 5 | `output/experiment3/` through `output/experiment6/` | `manuscript/figures/Figure 5.pdf` and `Figure 5.png` |
| Table 1 | All eleven analysis folders in `output/real data study/` | `manuscript/tables/Table 1.pdf` |
| Figure 6 | `data/sinha_2016_data.RData` and `data/sinha_2016_genera.tsv` | `manuscript/figures/Figure 6.pdf` |

Figures 3–5 and Table 1 summarize the saved results. Each copy of `Figure 5.R` in experiments 3–6 produces the complete Figure 5; run one copy. Table 1 follows the notebook aggregation and displays `-` in the S-N column. It also saves `output/real data study/Table 1 summaries.rds`.

Figure 6 runs data fission, model fitting and inference on the Sinha data. It also saves `CRC_inference.csv` and `CRC_Fusobacterium_contrasts_BH.csv` in `output/real data study/sinha_2016_binary/`.

### Rerun simulations and real-data analyses

Each runner processes one replication. Set the replication number with `SLURM_ARRAY_TASK_ID`:

```bash
SLURM_ARRAY_TASK_ID=1 Rscript --vanilla "code/run code/simulations/experiment1/run_cluster_experiment1.R"
SLURM_ARRAY_TASK_ID=1 Rscript --vanilla "code/run code/real data study/sinha_2016_binary/sinha_2016_binary.R"
```

Use `run_cluster_experimentN.R` for experiment `N`, or `<analysis>/<analysis>.R` for a real-data analysis. Experiments 1–5 and each real-data analysis use replication IDs **1–200**. Experiment 6 uses **1–400**. Results are saved in `output/experimentN/` and `output/real data study/<analysis>/`, respectively.

For Slurm, set `PROJECT_ROOT` in each `.sh` file to the absolute project path. Set `R_MODULE` and, for MATLAB experiments, `MATLAB_MODULE` to the cluster module names; leave them empty when the executables are already on `PATH`.

Submit all six simulations and eleven real-data analyses:

```bash
for n in 1 2 3 4 5 6; do
  sbatch "code/run code/simulations/experiment${n}/submit_experiment${n}_array.sh"
done

for script in "code/run code/real data study"/*/*.sh; do
  sbatch "$script"
done
```

The `.sh` files define the replication arrays and write results and runtime logs to the corresponding `output/` folders. After the jobs finish, run the figure and table commands above.
